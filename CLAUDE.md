## Build/Run/Test

```bash
# Build and run xv6 in QEMU
make qemu

# Build kernel only
make kernel/kernel

# Build filesystem image
make fs.img

# Run with GDB debugging
make qemu-gdb

# Run full user tests (600s timeout)
./test-xv6.py usertests

# Run quick subset of user tests
./test-xv6.py -q usertests

# Run crash recovery tests (log + orphan)
./test-xv6.py crash
```

Requires: RISC-V `riscv64-*-elf-` toolchain on PATH, and `qemu-system-riscv64` >= 7.2.

## Architecture

xv6 is a teaching OS reimplementing Unix V6 for RISC-V multiprocessors, used in MIT's 6.1810. The `zh-cn` branch is a Chinese translation variant based on the upstream `riscv` branch.

**Boot sequence**: `kernel/entry.S` (per-CPU entry) → `kernel/start.c` (machine-mode setup, switches to supervisor) → `kernel/main.c` (init subsystems, then `scheduler()`).

**Trap/syscall path**: User `ecall` → `trampoline.S` (uservec, switches to kernel page table) → `usertrap()` in `trap.c` → `syscall()` in `syscall.c` dispatches via `syscalls[num]()` table → return via `prepare_return()` → `trampoline.S` (userret).

**Process model** (`kernel/proc.h`): `struct proc` (PID, pagetable, trapframe, context for swtch, open files, cwd). `struct cpu` holds per-CPU state (current proc, scheduler context, interrupt nesting). Process states: UNUSED → USED → RUNNABLE → RUNNING → ZOMBIE/SLEEPING. `proc.h:86` defines p->lock rules: lock must be held for p->state, p->chan, p->killed, p->xstate, p->pid. `p->parent` is protected by `wait_lock`, not p->lock.

**Memory layout** (`kernel/memlayout.h`): Physical RAM starts at `0x80000000`, 128MB. QEMU maps UART at `0x10000000`, virtio disk at `0x10001000`, PLIC at `0x0c000000`. User virtual address space: text/data/bss → stack → heap → TRAPFRAME → TRAMPOLINE (at MAXVA - PGSIZE). Each process kernel stack sits below TRAMPOLINE with guard pages.

**File system**: Buffer cache (`bio.c`) → logging layer for crash safety (`log.c`, group writes as transactions) → inode/file layer (`fs.c`, `file.c`). `log.c` uses `begin_op()`/`end_op()` to bracket FS system calls; on boot `initlog()` recovers committed logs. The file system lives in `fs.img` built by `mkfs/mkfs.c`.

**Key headers**: `kernel/types.h` (basic types), `kernel/defs.h` (all function declarations, `NELEM`), `kernel/param.h` (tunable constants like `NPROC=64`, `NCPU=8`, `FSSIZE=2000`), `kernel/riscv.h` (RISC-V CSR access, inline asm), `kernel/memlayout.h` (physical/virtual memory constants).

**User programs** (`user/`): Linked with `ulib.o`, `usys.o` (syscall stubs generated by `usys.pl`), `printf.o`, `umalloc.o`. User entry point linked at address 0 via `user/user.ld`. The `_` prefix executables (e.g., `_cat`) are loaded into `fs.img`.

## Code style

- C files: 2-space indent, BSD style (`kernel/.dir-locals.el`). No tabs in `.c`/`.h`.
- Assembly (`.S`): 8-space indent.
- Makefile: tab indentation.
- `kernel/defs.h` is the central declaration header — add new kernel function prototypes there.
